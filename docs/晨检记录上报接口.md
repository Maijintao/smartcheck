# 晨检记录上报接口

## 1. 请求

正式环境必须使用 HTTPS，不允许使用 HTTP 或依赖重定向升级到 HTTPS。

```http
POST /api/device/morning-check/upload
Content-Type: application/json
api-key: {平台分配的 API Key}
```

当前版本一次只上报一名员工，`employees` 必须是数组且长度必须等于 `1`。

```json
{
  "device_id": "DEVICE001",
  "timestamp": 1786665600000,
  "employees": [
    {
      "employee_id": "E001",
      "name": "张三",
      "record_id": 1001,
      "record_uuid": "7ed7724e-cf2d-4b7d-a2e1-9a539e87bb24",
      "user_id": 1,
      "temperature": 36.5,
      "is_temp_normal": true,
      "is_hand_normal": false,
      "is_passed": false,
      "hand_status": "ABNORMAL",
      "has_foreign_object": true,
      "hand_abnormal_types": ["ring"],
      "health_cert_status": "VALID",
      "symptom_flags": ["COUGH"],
      "remark": "手部检出戒指",
      "photo": "/9j/4AAQSkZJRgABAQ...",
      "hand_palm_photo": "/9j/4AAQSkZJRgABAQ...",
      "hand_back_photo": null
    }
  ]
}
```

## 2. 请求字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|:---:|---|
| `device_id` | string | 是 | 设备稳定唯一编码；一条记录首次上传后固定，不随配置修改 |
| `timestamp` | long | 是 | 晨检时间，Unix 毫秒时间戳；重试时保持不变 |
| `employees` | array | 是 | 晨检记录数组，当前长度必须等于 `1` |
| `employees[].employee_id` | string | 是 | 平台下发的员工工号，平台按此字段匹配员工 |
| `employees[].name` | string | 是 | 晨检发生时的员工姓名快照 |
| `employees[].record_id` | long | 是 | 设备本地数据库记录编号，仅用于排查和追溯，不作为幂等键 |
| `employees[].record_uuid` | string | 是 | 设备生成的晨检记录 UUID，在单台设备内永久唯一 |
| `employees[].user_id` | long | 是 | 设备本地用户编号，仅用于追溯，不参与平台员工匹配 |
| `employees[].temperature` | float | 是 | 体温，单位为摄氏度 |
| `employees[].is_temp_normal` | boolean | 是 | 体温是否正常，`temperature < 37.3` 时为 `true` |
| `employees[].is_hand_normal` | boolean/null | 是 | 手部检查正常为 `true`，异常为 `false`，未检查为 `null` |
| `employees[].is_passed` | boolean | 是 | 设备最终判定，规则见第 5 节 |
| `employees[].hand_status` | string | 是 | `NORMAL`、`ABNORMAL` 或 `NOT_CHECKED` |
| `employees[].has_foreign_object` | boolean/null | 是 | 检出手部异物为 `true`，未检出为 `false`，未检查为 `null` |
| `employees[].hand_abnormal_types` | string[] | 是 | 检出的异物类型；正常或未检查时为 `[]` |
| `employees[].health_cert_status` | string | 是 | 晨检发生时的健康证状态快照 |
| `employees[].symptom_flags` | string[] | 是 | 不适症状列表，无症状时为 `[]` |
| `employees[].remark` | string | 是 | 备注，无备注时为 `""` |
| `employees[].photo` | string/null | 是 | 人脸照片的原始 Base64；无照片时为 `null` |
| `employees[].hand_palm_photo` | string/null | 是 | 手心照片的原始 Base64；无照片时为 `null` |
| `employees[].hand_back_photo` | string/null | 是 | 手背照片的原始 Base64；无照片时为 `null` |

同一员工在多台设备上的员工工号必须保持一致。设备使用平台员工同步数据中的 `employee_id` 原值，不使用本地 `user_id` 关联平台员工。

## 3. 幂等与冲突

- 唯一键为 `device_id + record_uuid`。
- `record_uuid` 在单台设备内永久唯一，格式为 UUID。
- 因网络超时等原因重试时，`device_id`、`record_uuid`、`timestamp`、全部业务字段和图片内容均保持不变。
- 平台再次收到相同唯一键和相同内容时，应按幂等成功处理，返回原平台记录 ID。
- 平台再次收到相同唯一键但内容不同时，必须返回 HTTP `409 Conflict`，不得覆盖原记录。

## 4. 枚举

### 手部状态

| `hand_status` | `is_hand_normal` | `has_foreign_object` | 说明 |
|---|:---:|:---:|---|
| `NORMAL` | `true` | `false` | 已检查，未检出异物 |
| `ABNORMAL` | `false` | `true` | 已检查，检出异物 |
| `NOT_CHECKED` | `null` | `null` | 未完成手部检查 |

`hand_abnormal_types` 可包含：

| 值 | 说明 |
|---|---|
| `band_aid` | 创可贴 |
| `bracelet` | 手链/手环 |
| `ring` | 戒指 |
| `watch` | 手表 |
| `foreign` | 其他异物 |

设备当前检测的是手部异物，不检测或上报伤口，因此接口没有 `has_wound` 字段。模型识别到的 `toilet_paper`（纸巾）和 `hand`（手部本身）不作为异常类型上报。

### 健康证状态

| 值 | 说明 |
|---|---|
| `VALID` | 有效，距到期超过 7 个自然日 |
| `EXPIRING_SOON` | 当天到期或 1 至 7 个自然日内到期，包含当天和第 7 天 |
| `EXPIRED` | 已过期 |
| `NOT_PROVIDED` | 未录入健康证或到期日期缺失 |
| `REVOKED` | 已吊销 |
| `NOT_CHECKED` | 未检查 |
| `UNKNOWN` | 无法识别或状态未知 |

日期边界按设备所在时区的自然日计算。该字段是晨检发生时的设备快照；平台员工主数据仍是健康证信息的最终来源。

### 症状

`symptom_flags` 可包含：`COUGH`、`FEVER`、`VOMITING`、`RUNNY_NOSE`、`RASH`、`HEADACHE`、`FATIGUE`、`SORE_THROAT`、`DIARRHEA`、`OTHER`。

## 5. 最终判定与一致性

设备上传的 `is_passed` 是最终权威结果。仅当以下条件全部满足时为 `true`：

- `temperature < 37.3` 且 `is_temp_normal = true`
- `hand_status = NORMAL`、`is_hand_normal = true`、`has_foreign_object = false`
- `health_cert_status` 为 `VALID` 或 `EXPIRING_SOON`
- `symptom_flags` 为空数组

平台应保存设备原始字段，并按上述规则校验字段一致性，不得静默改写 `is_passed`。字段互相矛盾时返回 HTTP `422 Unprocessable Entity`，整条记录不入库。

## 6. 图片约束

- 图片统一为 JPEG，最长边不超过 `1280` 像素。
- 每张 JPEG 压缩后不得超过 `2 MiB`。
- 三张图片的 Base64 字符总量不得超过 `9 MiB`，完整 JSON 请求体不得超过 `10 MiB`。
- 只允许原始 Base64 字符串，不允许 `data:image/jpeg;base64,` 前缀。
- 没有照片时传 JSON `null`，不传空字符串。
- Base64 无效、图片不是有效 JPEG 或超过限制时，平台返回 HTTP `422`；整条记录失败，不仅产生 warning。

## 7. 成功响应

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "recordIds": ["REC001"],
    "processTime": 120,
    "warnings": [],
    "capture_image_url": "/uploads/morning-check/face.jpg",
    "hand_palm_image_url": "/uploads/morning-check/palm.jpg",
    "hand_back_image_url": null
  },
  "request_id": "cf8ee2849bc34c5e8ad34a2d9997a0bd"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|:---:|---|
| `code` | int | 是 | 业务状态码，成功固定为 `200` |
| `message` | string | 是 | 处理结果说明 |
| `data` | object | 是 | 成功响应数据 |
| `data.recordIds` | string[] | 是 | 平台记录 ID 数组，当前长度必须等于 `1` |
| `data.processTime` | int | 是 | 平台处理耗时，单位为毫秒 |
| `data.warnings` | string[] | 是 | 非阻断警告，无警告时为 `[]` |
| `data.capture_image_url` | string/null | 是 | 人脸图片相对 URL |
| `data.hand_palm_image_url` | string/null | 是 | 手心图片相对 URL |
| `data.hand_back_image_url` | string/null | 是 | 手背图片相对 URL |
| `request_id` | string | 是 | 平台请求追踪 ID |

当前请求固定只有一条记录，因此成功响应中的 `data.recordIds` 必须存在且长度等于 `1`，顺序与 `employees` 一致。设备只在 HTTP 状态码为 `200`、业务 `code` 为 `200`，且 `recordIds` 恰好包含一个元素时确认上传成功。

## 8. 错误与重试

| 情况 | 设备处理 |
|---|---|
| 网络连接失败或超时 | 自动重试 |
| HTTP `408`、`429`、`5xx` | 自动重试 |
| HTTP `400`、`401`、`403`、`409`、`422` 及其他 `4xx` | 停止自动重试，保存失败原因并报警/供排查 |
| HTTP `200` 但业务 `code >= 500` | 自动重试 |
| HTTP `200` 但其他非 `200` 业务码 | 停止自动重试 |
| HTTP `200`、业务 `code = 200`，但 `recordIds` 缺失或长度不为 `1` | 停止自动重试，按响应协议错误处理 |

可重试错误采用指数退避：`1、2、4、8、16、32、60` 分钟，之后保持每 `60` 分钟重试。永久错误不会自动重试。
