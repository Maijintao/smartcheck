## 一、SM4 国密加解密规范

### 1.1 适用范围

所有非排除路径下的 **POST / PUT / PATCH** 请求（请求体加密）、**JSON 格式响应**（响应体加密）。

> **GET 请求不加密。**

### 1.2 算法参数

| 参数 | 取值 / 说明 |
|------|-------------|
| 加密算法 | SM4（国密算法），CBC 模式 |
| 密钥（Key） | 16 字节固定长度（由平台分配） |
| 初始向量（IV） | 16 字节固定长度（由平台分配） |
| 填充方式 | **0 字节填充** — 数据长度不足 16 的整数倍时，末尾补 `\x00`，解密后去除末尾 0 填充 |
| 编码格式 | 明文 → UTF-8 字节 → SM4 加密 → **16 进制字符串**（加密结果） |

### 1.3 算法流程

**加密：**
```
明文字符串 → UTF-8 转字节 → 0 填充至 16 的整数倍 → SM4-CBC 加密 → 加密字节转 16 进制字符串
```

**解密：**
```
16 进制字符串 → 转加密字节 → SM4-CBC 解密 → 去除末尾 0 填充 → UTF-8 转明文字符串
```

### 1.4 请求体格式要求

1. 将请求参数组装为合法 JSON 字符串；
2. 对 JSON 字符串执行 SM4 加密，得到 16 进制字符串；
3. 将 16 进制字符串作为**唯一请求体**发送（无需嵌套，直接传该字符串）；
4. 请求头无需特殊设置（后端自动处理 `Content-Type: application/json`）。

### 1.5 解密容错规则

后端解密前执行以下校验 / 清理：
1. 清理请求体中所有非 16 进制字符（`0-9`、`a-f`、`A-F`）；
2. 校验 16 进制字符串长度为偶数（1 字节 = 2 个 16 进制字符）；
3. 校验加密字节长度为 16 的整数倍（SM4-CBC 要求）；
4. 解密后验证数据为合法 JSON，否则返回 `400` 错误。

### 1.6 加密示例

**明文 JSON：**

## 二、通用请求规范

### 2.1 请求头

| Header | 必填 | 说明 |
|--------|------|------|
| `Token` | 是（登录接口除外） | 登录成功后返回的 token，未登录前传空字符串 |
| `SmKeys` | 是 | 国密 Key，固定值由平台分配 |
| `apisix` | 否 | **仅测试环境需要**，正式环境无需此头。示例值：`djdhJSJSHDHQK2,66556sskakjdajdj@@curls` |

### 2.2 统一响应结构

所有接口返回统一格式的 JSON（需 SM4 解密后得到）：

```json
{
    "statuCode": 200,
    "info": "查询信息成功",
    "data": {},
    "filter": {}
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `statuCode` | integer | 状态码，`200` 为成功，其他为业务错误 |
| `info` | string | 响应信息描述 |
| `data` | object / array / null | 业务数据，根据接口不同类型不同 |
| `filter` | object / null | 请求参数回显或附加过滤条件 |

## 附录：接入注意事项

1. **SM4 加解密是所有 POST/PUT/PATCH 接口的前置条件**，GET 接口的请求参数直接以 Query 形式传递，响应仍需解密。
2. **Token 有效期**由服务端控制，过期后需调用登录接口重新获取。
3. **测试环境**需额外添加 `apisix` 请求头，**正式环境无需此头**。
4. **图片字段**（`portraitPhoto`、`healthUrl`、`health_image`、`face_image`、`picture_img` 等）在上传时为 Base64 编码，在响应中可能返回 URL 或 null。
5. **人员新增**接口若人员已存在会失败，建议先调用「人员管理」接口查询确认。
6. **`health_certificate_state`** 字段：上传时使用 `boolean`（`true`/`false`），响应回显时为 `integer`（`1`/`0`）。
